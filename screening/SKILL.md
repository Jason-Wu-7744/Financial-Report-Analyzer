# 上市公司致命风险排雷

将用户给出的日期视为信息截止日，按 V3.0 框架完成 19 项硬性排雷并输出中文 Word 报告。先读 [framework.md](references/framework.md)，再读 [evidence-and-edge-cases.md](references/evidence-and-edge-cases.md)；生成报告前读 [report-contract.md](references/report-contract.md)。

## 工作流

1. 解析公司简称、法定全称、证券代码、上市地、所属行业、排雷日期和数据截止时点。用户写“今天是……”时，以该日期为准，不改成系统当前日期。
2. 搜集证据。优先使用公司公告/交易所文件、审计年报、政府与监管机构文件；再用可靠行情或金融数据库补充估值、涨跌幅、股东和标准化指标。涉及最新事实时必须联网核验。
3. 建立证据账本：每个事实记录来源编号、标题、URL、发布日期、访问日期、适用口径和数据期。不得将搜索摘要、二手转载或无链接说法当作关键红线的唯一依据。
4. 按 H1→H2、C1→C11、Q1→Q6 顺序判定。每项 `evidence_state` 必须为“已核验未触发”“已核验触发”“证据不足”“不适用”之一；兼容字段 `outcome` 对应“通过”“高风险”“证据不足”“通过（不适用）”。不适用须明确行业或数学原因。不得使用打分、星级或 A/B/C 分类。
5. 严格执行一票否决：任何一项“高风险”即最终“淘汰”，其他优点不得抵销。为完整留档，默认仍完成全部 19 项；若用户明确要求极速筛查，可在命中后终止，但报告必须注明未执行项目。
6. 将未达到硬阈值但值得深研的事项列为“补充黄灯/观察项”，不得用黄灯改变硬结论。
7. 将结果整理为 `report.json`，按 [report-contract.md](references/report-contract.md) 校验。结论和命中数由19项结果推导：有已核验触发则淘汰；无触发但有证据不足则待补证；全部核验完成才通过。已核验项必须保留可在提供原文定位的 `evidence_quote`、期间、口径和页码。
8. 使用工作区依赖加载器取得 Python 路径，运行：

   ```bash
   "$PYTHON_BIN" scripts/build_report.py report.json --output final.docx
   ```

9. 使用已安装的 `documents` 技能渲染最终 DOCX，逐页检查所有 PNG。修复截断、表格溢出、字体替代、空白页、页眉页脚或分页问题后重新生成并渲染，直至通过。
10. 仅交付最终 DOCX。报告名称采用“公司简称(代码)致命风险排雷报告_YYYYMMDD.docx”。

## 关键纪律

- 不编造数据、来源、处罚、减持、授信、估值分位或账龄。证据不足时继续检索；仍无法证明“通过”时，先输出缺口清单并补证，不得把“未查到”直接写成“通过”。
- 区分 AND 与 OR。框架写“且/同时”时必须全部满足；写“任一子条件”时任一满足即可命中。
- 判断未触发时同样遵循逻辑：AND只需一个必要条件有直接证据为假，可保留其他条件的资料缺口而不误降级；OR须全部子条件已被排除。用`proof_type`记录证明方式，AND另给`disproven_condition`。Q1/Q4/Q5数值反证须保留可复算分子、分母、比例、阈值、期间、单位及分别的直接引文。
- C8上市年限只能用实际上市/IPO日期或已上市年限的直接原文核验。证券代码、报告标题及“长期上市公司”常识均不是上市年限证据。
- 所有说明、限制段和最终结论卡必须与最终19项证据状态一致。C8因缺直接证据保留“证据不足”时，finding和限制段不得同时声称“长期上市已通过”。
- 来源`published_at`仅表示实际引用文件的公开披露日；不要用分析日、董事会批准日或财报期末代填。港交所文件日期须与实际引用的文件对应，未知保留“未核实”。
- 区分公司、实控人、现任高管和历史高管；准确写明官方事实所处阶段，不把“涉嫌/移送审查起诉”写成“已判刑”。
- 只用截止日之前已公开的信息。财报期、公告日、行情日必须同时标明，避免未来信息穿越。
- 核心结论附近使用 `[S1]` 形式的来源编号；报告末尾列出可点击链接、公式、数据限制和免责声明。
- “排雷通过”只表示未发现框架定义的致命风险，不表示值得投资。
- 港股须按财报声明的 HKFRS/IFRS 及綜合报表口径取证，兼容繁体/英文科目；經調整溢利不得冒充A股扣非净利润。
- 金融企业使用适用的行业监管指标，不因工业企业指标“不适用”而误判高风险。
- JSON 输出必须控制篇幅并完整包含19项检查；生成中断或格式不完整时重试，失败项保留为可续跑状态，不覆盖其他公司的已完成结果。
- 排雷生成至多两次全量尝试；只保留原始JSON中已完整闭合、ID唯一且必填证据字段齐全的检查对象，不补闭合单项或猜测半句。仍缺项时仅按缺失ID以每批最多5项、最多4批定向补写。最终不足19个唯一ID或补写重复/错ID仍标失败可重试；记录完成ID及截断原因用于诊断。
- 长报告按主题均衡保留损益、现金流、资产负债、债务、减值、分部与监管等原文。不能仅截取开头，也不能把已省略材料视为已核验。
- 当前自动化流程仅引用实际取得的原文和数据；未经执行的全网检索、三年审计核查、行情历史分位和监管查询一律不得声称已完成。

## 输出质量门

在生成 Word 前确认：19 个 ID 齐全且无重复；每项包含阈值、实测/事实、结论、依据、来源；所有公式可复算；所有高风险均有高质量证据；结论与命中项一致；淘汰报告含 6 个月冻结期及复核日期；通过报告列出进入深度研究后必须验证的问题。
