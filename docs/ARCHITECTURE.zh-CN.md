# 技术架构与工程决策

[English](ARCHITECTURE.md) · [中文首页](../README.zh-CN.md)

## 工作流程

公司标识或上传工作簿 → CNINFO/HKEX 财报检索 → 主体、期间、报告类型检查 → 保留物理页码的 PDF 抽取 → 证据选择与主表保留 → 快评、七章研究简报或独立风险核验 → 结构、引用、算式、会计口径检查 → 定向重试或明确证据缺口 → 保存工作区 → 可选英文翻译与保护标记检查 → Markdown、工作簿和文档导出。

## 规则与模型如何配合

语言模型用于组织叙述性披露，不能自行确定会计口径，也不能把缺少披露解释为没有风险。Python 负责证据选择、状态流转、显式算式检查和导出校验；版本化 Markdown 指令规定模型的分析及报告约定。两者都不能证明经济解释正确，重要结论仍需要回到原始财报核验。

系统保留“已核验未触发、已核验触发、证据不足、不适用”四种状态，避免把检查失败混同于负面发现不存在。

## 检查点与翻译

财报下载、网络调用、生成和翻译可以分别失败。按公司及语言保存的检查点支持从失败阶段继续，不必重新生成所有成功部分。后台模型密钥通过进程环境传递，不写入保存的请求 JSON。

英文产物由原语言报告翻译而来，并保护数字和引用。原文与翻译分开保存；语言或标记检查失败需要保持可见、支持重试。通过检查只表明受保护内容一致，不能证明底层财务判断正确。

## 当前取舍

- 系统仍是研究原型，编排模块较大；进一步拆分检索、校验和展示层有助于维护。
- 存储依赖本地文件与后台进程，多实例需要更强的任务协调和存储隔离。
- 登录门禁用于本地评审。公开服务还需要完善身份管理、限流、TLS、密钥管理和运行监控。
- 财报版式变化、扫描件、遗漏附注及模型错误会影响抽取和推断。
- 下载和模型延迟随条件变化，当前版本不声称经过基准测试或财务准确率审计。
